What Each File Does:
====================

[Raspberry Pi Side]

setup_pi.sh:
  - Installs Mosquitto MQTT broker (port 1883)
  - Installs Python 3 + pip + virtualenv
  - Creates Python virtual environment
  - Installs Flask, SocketIO, paho-mqtt, numpy
  - Configures Mosquitto for local dev (no auth)
  - Tests MQTT connection
  - Displays network info

dashboard_server.py:
  - Flask web server (port 5000)
  - MQTT client (subscribes to eew/stream/#, eew/heartbeat/#, etc.)
  - Real-time data processing:
    * Receives 200 Hz acceleration stream
    * Calculates STA/LTA ratio
    * Maintains buffers for charts
  - WebSocket server (Socket.IO):
    * Pushes updates to browser at 20 Hz
    * Emits: stream_update, stats_update, trigger_event
  - REST API endpoints:
    * GET /api/stats - Node statistics
    * GET /api/triggers - Recent triggers
    * GET /api/stream - Current stream buffer

templates/dashboard.html:
  - Single-page web app
  - Chart.js for real-time graphs:
    * 3-axis acceleration (X/Y/Z)
    * STA/LTA ratio with threshold line
  - Statistics display:
    * RMS, Kurtosis, Peak Frequency
    * Roll, Pitch, Node ID
    * Trigger count
  - Trigger event log with visual alerts
  - WebSocket client (Socket.IO)
  - Responsive dark theme UI

[ESP32 Side]

dual_mqtt.h/cpp:
  - Manages TWO MQTT connections:
    * Cloud (HiveMQ): TLS, authenticated, triggers/heartbeats
    * Dev (Pi): No TLS, no auth, all data + streaming
  - Methods:
    * begin() - Connect to both brokers
    * loop() - Maintain both connections
    * publishStreamSample() - Send x/y/z at 20 Hz (dev only)
    * publishTrigger/Heartbeat/Status() - Send to both
  - Rate limiting: 200 Hz → 20 Hz for MQTT (every 10th sample)
  - Independent reconnect logic for each broker

MQTT Topics:
============

Production (HiveMQ Cloud):
--------------------------
eew/register                - Node registration
eew/heartbeat/{node_id}     - Status every 10s
eew/raw/{node_id}           - Trigger waveforms
eew/status/{node_id}        - Command responses
eew/cmd/{node_id}           - Commands (subscribe)
eew/alert                   - Earthquake alerts (from server)

Development (Raspberry Pi):
---------------------------
All production topics PLUS:
eew/stream/{node_id}        - Real-time acceleration (20 Hz)
                              Format: {"x": 5.2, "y": -1.3, "z": 1005.8, "timestamp_ms": 12345}

Data Flow:
==========

ESP32 (200 Hz sampling)
  ↓ Every sample
  Calibration → Trigger detection
  ↓ Every 10th sample (20 Hz)
  publishStreamSample(x, y, z)
  ↓
MQTT Dev Broker (Mosquitto on Pi)
  Topic: eew/stream/Node_XXXX
  QoS: 0 (best effort)
  ↓
dashboard_server.py
  MQTT subscriber
  ↓ On message
  Calculate STA/LTA, store in buffer
  ↓ Emit via WebSocket
  Socket.IO → Browser
  ↓
dashboard.html
  Chart.js → Update graphs
  Display stats

Troubleshooting:
================

Dashboard "Disconnected":
  → Check: ps aux | grep dashboard_server
  → Start: python3 dashboard_server.py

No data on charts:
  → Check ESP32 serial: Should see "[MQTT] ✓ Dev broker connected"
  → Check Mosquitto: sudo systemctl status mosquitto
  → Test MQTT: mosquitto_sub -h 192.168.31.28 -t 'eew/#' -v

ESP32 can't connect to dev broker:
  → Verify IP in config.h matches Pi: 192.168.31.28
  → Check same WiFi network
  → Ping from ESP32 to Pi (if possible)
  → Check firewall: sudo ufw allow 1883

Charts freeze:
  → Network congestion (reduce stream rate in dual_mqtt.cpp)
  → Pi overloaded (check: top)

Development vs Production:
==========================

Development Setup (this):
  - Local MQTT broker (no encryption)
  - Full 200 Hz data streaming
  - Real-time visual debugging
  - Web dashboard
  - Higher network/CPU usage
  - Use during:
    * Initial testing
    * Threshold tuning
    * Algorithm development
    * Debugging trigger issues

Production Setup (existing):
  - Cloud MQTT (HiveMQ, encrypted)
  - Only triggers + heartbeats
  - Lower network usage
  - Mobile app alerts
  - Use for:
    * Deployed nodes
    * Long-term monitoring
    * Multi-city network

Both can run simultaneously! ESP32 publishes to both brokers.

To disable dev mode later:
  Set in config.h: #define ENABLE_DEV_BROKER false

Performance Notes:
==================

Network bandwidth (per node):
  - Dev streaming: ~40 KB/s (20 Hz × 128 bytes JSON)
  - Production: ~1 KB/s (heartbeat every 10s)

Pi 4 can handle:
  - 5-10 nodes streaming simultaneously
  - More if you reduce stream rate (change _stream_counter in dual_mqtt.cpp)

ESP32 RAM usage:
  - Dual MQTT adds ~8 KB (two WiFi clients)
  - Streaming adds minimal overhead (rate-limited)

Browser performance:
  - Chart.js handles 1000+ points smoothly
  - Older browsers may lag (use Chrome/Edge/Firefox)
